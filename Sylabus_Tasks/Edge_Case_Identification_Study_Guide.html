Edge Case Identification for Students

Spot the tricky inputs before they break your program!

1. Introduction: What is an Edge Case?

An Edge Case is an input at the very boundary limit (or just outside) of what a software program expects to handle.

Core Rule: Bugs love to hide at the edges! Most programmers test ordinary inputs, but programs usually crash when fed extreme, boundary, empty, or unexpected values.

Edge cases live at the very edges: the smallest, the largest, the first, the last, or nothing at all.

Everyday Metaphor: The Lift (Max 8 People)

  • 0 People: Empty lift (Special edge case: Should it travel? Does it enter standby mode?)
  • 1 to 7 People: Everyday rides (Normal zone: works as planned).
  • 8 People: Exactly full (Limit edge case: Maximum capacity reached, but still permitted).
  • 9+ People: Overload (Out of boundary: Alarm rings, doors stay open, refuses to move).

2. Normal Zone vs. Edge Cases vs. Invalid Range

Rule: Examination marks must be between 0 and 100.

Zone Input Values Description Expected System Behavior
Too Low (Invalid) -1, -50 Strictly lower than allowed minimum Reject with error validation
Lower Edge 0, 1 Right on the boundary and immediately inside Accept
Normal Zone 2 to 98 Everyday typical inputs (e.g., 50, 75) Accept
Upper Edge 99, 100 Immediately inside and exactly on the maximum Accept
Too High (Invalid) 101, 200 Strictly higher than allowed maximum Reject with error validation

3. Why Should We Care? (Real-World Failures)

When edge cases are missed, applications fail in unexpected and costly ways:

  • Shopping App: Quantity set to 0 or negative. Result: An order for 0 items is placed, or cost is subtracted from the total.
  • Video Game: Score exceeds maximum integer capacity. Result: Integer overflow flips score to negative numbers (-2,147,483,648).
  • Registration Form: Age field filled with -5. Result: Form accepts a negative age, corrupting database records.

4. Boundary Value Testing: "Below, On, Above"

At every boundary limit, test three specific locations:

  1. Just Below: One step under the boundary
  2. Exactly On: Right on the limit line
  3. Just Above: One step over the boundary

Applying to Marks (0 to 100):

  • -1 (Just below lower boundary) → Reject
  • 0 (On lower boundary) → Accept
  • 1 (Just inside lower boundary) → Accept
  • 50 (Middle normal value) → Accept
  • 99 (Just inside upper boundary) → Accept
  • 100 (On upper boundary) → Accept
  • 101 (Just above upper boundary) → Reject

5. The "Sneaky Five" Inputs Checklist

Whenever you test any input or function, always evaluate these 5 scenarios:

  1. Empty ("", null, []): Nothing typed or empty list.
  2. Zero (0): Can we divide by it? Does it cause division by zero?
  3. Negative (-1): Values less than zero when only positive is sensible.
  4. Huge / Maximum (MAX_VALUE): Large numbers or huge text that cause memory or integer overflow.
  5. Wrong Type ("abc"): Text entered where numbers are expected.

6. Java Code Example: An Edge Case Bug

Buggy Code:

int[] marks = {};   // Edge case: Empty array!
int sum = 0;
for (int m : marks) {
    sum += m;
}
// marks.length is 0 -> Evaluates 0 / 0!
int avg = sum / marks.length; // CRASH: ArithmeticException: / by zero!

The Fix:

// Always handle the edge case before dividing:
if (marks.length == 0) {
    return 0;
}
int avg = sum / marks.length;
return avg;

7. The 4-Step "Edge Detective" Methodology

  1. Step 1: Read the Rule: What values are allowed? (e.g., 1 to 10)
  2. Step 2: Find the Limits: Identify the smallest and biggest permitted values (1 and 10).
  3. Step 3: Pick Tests: Select values below, on, and above each limit (0, 1, 10, 11).
  4. Step 4: Run and Fix: Test the code, patch any crashes, and retest.

8. Hands-on Practice: Password Rule (6 to 12 Characters)

Password Length Category Expected Result
0 (Empty) Edge Case Reject (Must not be blank)
5 Edge Case (Just below) Reject (Too short)
6 Edge Case (On limit) Accept
8 Normal Zone Accept
12 Edge Case (On limit) Accept
13 Edge Case (Just above) Reject (Too long)

9. Quick Quiz & Knowledge Check

  • Q1: Pizza orders allow 1 to 10. Which tests are edge cases? → Answers: 0, 1, 10, 11.
  • Q2: A list of student marks is empty. What error occurs? → Divide by zero (ArithmeticException).
  • Q3: An age box allows 1 to 120. Is 0 a normal test? → No, it is a boundary edge case.
  • Q4: Typing "abc" in a number box is what kind of test? → Wrong type (part of the Sneaky Five).
